# 宠物记忆产品：微信小程序工程决策

版本：v0.3  
首次确认：2026-07-20  
更新：2026-07-26  
状态：已确认的 M0/M1 工程基线；M0 开工前计划复核已完成，代码尚未实施

阶段：本文同时约束 `M0 — 本地 Mock 骨架`的可替换客户端边界，以及 `M1 — CloudBase Private Alpha`的真实后端、安全与环境边界。各小节必须明确其适用阶段，不能把 M1 能力提前伪装进 M0。

## 1. 目的与范围

本文将 [正式 MVP 决策书](../mvp/2026-07-20-formal-mvp-decision.md) 转化为首个可开发的工程边界。它只确定第一版的客户端、后端、数据与安全结构；不替代产品规则，也不直接创建腾讯云或微信平台资源。

## 2. 已确认的技术决策

| 层级 | 决策 |
|---|---|
| 客户端 | 微信小程序优先，使用 `uni-app + Vue 3 + TypeScript` 开发 |
| 开发工具 | CLI 工程管理源码、依赖、构建和测试；HBuilderX 用于打开工程与 uni-app 开发辅助；微信开发者工具负责小程序模拟器、真机预览与上传 |
| 后端 | 腾讯云 CloudBase：云函数、云存储、文档型数据库 |
| 架构风格 | 单一小程序 + 少量职责明确的云函数；不引入多服务、微服务或多智能体架构 |
| AI | 仅由云函数调用；小程序端不保留模型密钥、不直接请求模型服务 |
| 数据默认值 | 所有用户内容默认私密；线上、测试与开发环境完全隔离 |

M0 采用 uni-app Vue 3 CLI 工程，不使用 HBuilderX 原生工程目录。开发构建输出位于 `dist/dev/mp-weixin`，生产构建输出位于 `dist/build/mp-weixin`；两者都只能用于预览、调试或上传，不是源码编辑目录。HBuilderX 可以打开 CLI 工程提供 uni-app 开发辅助，但可重复执行的构建与测试以 `package.json` 脚本为准。 [uni-app CLI 快速上手](https://uniapp.dcloud.net.cn/quickstart-cli)

CloudBase 提供小程序所需的身份、云函数、文档数据库和文件存储能力，适合作为邀请制 MVP 的一体化后端；未来客户端或后端扩展时，以云函数接口为边界迁移，而不是让页面直接依赖数据库实现。 [CloudBase 小程序架构](https://cloud.tencent.com/document/product/876/20232)

## 4. 客户端与预览工作流

1. 在 `apps/pet-memory-miniapp/` 创建 uni-app Vue 3 + TypeScript CLI 工程并锁定依赖；
2. 使用 `npm run dev:mp-weixin` 生成开发产物，使用 `npm run build:mp-weixin` 生成生产产物；
3. HBuilderX 打开该 CLI 工程提供 uni-app 编辑与运行辅助；微信开发者工具导入 `dist/dev/mp-weixin` 进行开发调试，发布前导入并核验 `dist/build/mp-weixin`；
4. Claude Code 从仓库根目录读取产品文档，但只修改获准的 `apps/`、`services/` 与对应文档；
5. 每个功能切片先执行类型检查、单元测试与构建，再经过微信模拟器和真机预览，验证相册权限、键盘、页面滚动、返回与退出行为；
6. 只有通过验收的构建才进入邀请制测试环境。

不允许手改 `dist/`。该目录必须被 Git 忽略，避免生成物覆盖源码或产生无意义的代码评审差异。若 HBuilderX 或其他工具额外生成 `unpackage/`，同样必须忽略且不得作为正式构建输入。

## 5. 环境隔离

上线前必须创建三个独立 CloudBase 环境，并使用不同配置：

| 环境 | 用途 | 允许的数据 |
|---|---|---|
| `dev` | 日常开发、模拟器和功能调试 | 假数据、开发者自己明确提供的测试素材 |
| `staging` | 邀请制测试前的真机验收 | 经过同意的少量测试数据，不作为正式长期存储承诺 |
| `prod` | 后续正式私密测试与真实用户使用 | 真实用户内容，只能由授权流程处理 |

禁止把 `prod` 环境 ID、真实照片、AI 密钥或管理员凭据放进源码、页面配置、截图或聊天记录。CloudBase 支持将数据库、存储等资源按环境组织；环境隔离是本项目的工程要求，而不是可选优化。 [CloudBase 环境说明](https://cloud.tencent.com/document/product/876/18438)

## 6. 数据与云函数边界

### 6.1 领域数据

M1 只建立下列集合或等价的数据实体：

- `users`：用户身份与必要偏好；
- `memory_spaces`：一只 Ta 对应的私密空间；
- `assets`：照片等原始素材的元数据与归属；
- `memory_drafts`：未完成的用户记录和未确认 AI 草稿；M0 与 M1 的业务层均保证每个空间最多一条进行中的记录草稿；
- `memory_items`：用户确认保留的记忆片段；
- `ai_drafts`：可追溯到原始素材的 AI 整理候选；
- `consents`：AI 处理、未来提醒或分享等可撤回授权。

原始照片和原话不被 AI 整理稿覆盖。任何记忆片段均需能回溯到用户提供的原始内容。

### 6.2 云函数职责

M1 云函数按业务能力而不是页面命名，预留：

- `bootstrapUser`：建立或读取当前微信用户的最小资料；
- `memorySpace`：创建、读取、编辑、删除记忆空间；
- `memoryItem`：创建草稿、保存原话、确认记忆、列表与详情读取；
- `mediaAsset`：校验上传归属、记录素材元数据、生成私密访问地址；
- `aiMemoryDraft`：验证 AI 授权、传递允许的素材、生成整理草稿；
- `privacyRequest`：导出、删除与账户数据请求。

每个函数必须在服务端验证当前用户是否拥有目标空间和素材。小程序页面不得自行构造跨用户 ID 读取或写入数据。

## 7. 隐私与媒体安全

1. 数据库和云存储不允许默认公开读取；每条记录和每个文件均绑定创建者与记忆空间；
2. 图片上传可以由小程序端直传云存储以避免经云函数转发大文件，但上传路径、归属校验和最终素材记录必须受云函数与安全规则控制；
3. 图片展示使用短时、受控的访问地址，不把永久公开链接写进记忆文本或日志；
4. 所有删除操作必须同时处理数据库关联、草稿状态与存储对象，并向用户说明删除范围；
5. 云函数日志不得输出照片内容、完整原话、访问令牌、AI 密钥或用户身份映射；
6. 开发与验收中不使用真实用户照片作为演示素材，除非当事人明确同意且素材只留在约定环境。

CloudBase 的客户端能力可直接访问数据库和存储，但客户端代码天然可被观察；本项目因此将敏感写入、授权判断和 AI 操作收敛在云函数中，而非依赖页面隐藏逻辑。 [CloudBase 调用方式与客户端鉴权说明](https://cloud.tencent.com/document/product/876/19369)

## 8. AI 调用与失败降级

```text
小程序页面
→ aiMemoryDraft 云函数
→ 授权与所有权校验
→ 最小化、可追溯的素材载荷
→ 模型服务
→ 可编辑 AI 草稿
→ 用户确认后才创建或更新正式记忆
```

- 模型服务商、具体模型和密钥不在本次工程决策中锁定；它们由后续 AI 接入决策确定；
- 云函数只发送用户本次明确授权的文本和必要图片，不把整个记忆空间默认发送给模型；
- 模型不可用、超时、输出不符合约束时，保留用户原话与草稿，提示“暂时无法整理”，但不阻塞保存；
- 每个 AI 草稿记录使用的规则版本与来源素材 ID，方便问题追溯和用户删除；
- 上线前必须以编造事实、拟人发言、夸大愧疚、心理治疗承诺和敏感退出等反例做回归测试。

## 9. 设计系统与交互规范的落点

设计不是散落在页面 CSS 中。首个工程切片必须先建立：

- 色彩、纸张质感、字阶、间距、圆角、描边与阴影令牌；
- 主按钮、次按钮、文字操作、入口卡、输入区和安全出口的组件规范；
- 每个按钮的可见条件、禁用条件、点击结果、加载态、失败态、取消态与数据保存规则；
- 页面级状态：首次进入、空数据、有草稿、加载、错误、无权限、保存成功与安全退出；
- 以“查看也是完整使用”为原则，不用强制完成、打卡或不可预期跳转推动用户。

具体按钮与页面交互在后续逐页规格中确认；未经规格确认，实施方不得以“通用产品习惯”自行补充情绪引导、提醒或分享动作。

M0 的状态管理、Repository、本地快照、路由白名单、设计令牌、组件边界和分层测试策略，以 [M0 工程骨架与设计系统决策记录](../specs/2026-07-21-initial-engineering-skeleton-and-design-system-decisions.md) 为直接实施约束。精确依赖版本必须在创建 CLI 脚手架时根据兼容矩阵锁定并提交 lockfile，不在决策文档中填写未经安装验证的版本号。

## 10. M0 至 M1 实施切片

工程计划应按可验收闭环拆分，而不是按页面堆叠：

1. CLI 工程骨架、设计令牌、路由、Pinia、Repository、本地假数据与基础单元测试；
2. 记忆空间首页与空状态、最近留下、只查看路径；
3. 真实原话记录、草稿与安全退出；
4. CloudBase 身份、空间和记忆数据的私密读写；
5. 真实照片选择、受控上传、展示和删除；
6. AI 整理草稿、用户确认与失败降级；
7. 导出、删除、环境验收和邀请制测试准备。

每个切片开始前必须先有页面/交互规格和验收条件；完成后必须在微信开发者工具和真机上核验。
