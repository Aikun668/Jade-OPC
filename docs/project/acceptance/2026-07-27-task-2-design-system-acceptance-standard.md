日期：2026-07-27  
状态：正式验收门槛  
适用范围：M0 Task 2.1–2.9

## 1. 文档职责

本文件把 Task 2 的正式规格转换为可以逐项执行、逐项拒绝和逐项取证的子验收门。

本文件是验收标准，不是某一轮实现报告。Builder 和 Reviewer 不得为了让现有实现通过而降低、删除或改写这里的门槛。当平台能力与本标准确有冲突时，应先提供复现证据和 A/B 方案，由项目负责人确认后再同步修改正式规格与本文件。

## 2. 验收角色与权限

| 角色 | 本文件中的职责 |
|---|---|
| 项目负责人 | 确认接口、视觉或平台冲突导致的方案变化；完成人工视觉和真实工具操作 |
| Codex / 规划者 | 维护验收门槛、处理规格冲突、执行关键里程碑验收 |
| DeepSeek Builder | 实现、运行验证、提交证据；不能自行降低门槛或宣布 `accepted` |
| 独立 Reviewer | 使用新上下文只读复核，执行反证抽查并给出验收建议 |

Builder 只能把子项报告为 `self-verified`。只有独立 Reviewer 或关键验收者确认后，子项才能标记为 `accepted`。

## 3. 通用验收模型

### 3.1 子项状态

```text
not-started
→ implementing
→ self-verified
→ reviewer-accepted
```

发现问题时：

```text
self-verified
→ needs-fix
→ implementing
```

外部工具暂时不可用时：

```text
self-verified
→ externally-blocked
```

`externally-blocked` 必须写明唯一外部阻碍、已完成证据和补验方式，不能用来豁免代码、测试或产物错误。

### 3.2 三层证据

每个子项根据风险使用以下证据：

| 证据层 | 证明内容 |
|---|---|
| `M` 机器门 | 接口、状态、失败路径、类型、构建和禁止项能够被自动验证 |
| `A` 产物门 | 直接检查 PNG、manifest、WXSS、微信构建目录等真实交付物 |
| `H` 人工门 | 检查微信运行、响应式、键盘、手势、材质和系统差异 |

自动测试不能替代必要的微信运行与视觉检查，人工观察也不能替代可以自动验证的固定合同。

### 3.3 反证要求

每个 Task 2 子项至少选择一个关键条件执行反证抽查：

1. 临时模拟一种明确错误；
2. 确认对应验证会失败；
3. 恢复正确实现；
4. 重跑并确认通过。

反证可以通过测试夹具、参数注入或 Reviewer 的临时本地检查完成。不得把故意错误保留在仓库中。

### 3.4 通过定义

一个子项只有同时满足以下条件才可 `reviewer-accepted`：

- 所有强制 `M` 项通过；
- 所有强制 `A` 项通过；
- 标记为必需的 `H` 项完成，或真实登记为外部阻碍；
- 反证抽查证明关键测试能够发现错误实现；
- 没有未获批准的接口、依赖、视觉或产品变化；
- 没有 `TODO / FIXME / 以后替换 / placeholder` 等未完成内容；
- 证据包含命令、退出码、产物位置和真实 warning。

## 4. Task 2.1：全局令牌与基础样式

### 4.1 验收目标

建立唯一、可追溯的设计令牌和全局基础样式，使后续组件不再自行发明颜色、字号、间距、圆角、阴影、动效和热区。

### 4.2 机器门

- `T2.1-M01`：规格第 4 节要求的颜色令牌全部存在，名称和值精确一致。
- `T2.1-M02`：字体、字重、行高、间距、语义间距、圆角、边框、阴影、控件、热区和动效令牌全部存在且值精确一致。
- `T2.1-M03`：照片、草稿、布局和反馈时序使用的共享令牌存在，并且没有相同职责的重复令牌。
- `T2.1-M04`：禁止的中间字号、额外阴影和未经确认的颜色不出现在共享令牌或普通组件中。
- `T2.1-M05`：组件不得使用 `darken()`、`lighten()`、透明度叠加等方式派生新的产品颜色。
- `T2.1-M06`：`globals.scss` 只包含画布、系统字体、盒模型、文本继承、运行时变量和减少动态效果规则。
- `T2.1-M07`：全局页面不包含纸纹、噪点、胶带或局部组件材质。
- `T2.1-M08`：减少动态效果开启时，非必要动画和过渡降为 `0ms`。
- `T2.1-M09`：全局样式只在应用级产物中生效一次，不重复注入每个组件的 WXSS。
- `T2.1-M10`：全局样式和令牌文件不读取 Store、Repository、路由或平台业务数据。

### 4.3 产物门

- `T2.1-A01`：检查 `src/styles/tokens.scss`，每个令牌均可追溯到正式规格。
- `T2.1-A02`：检查生产 `app.wxss`，画布、字体、正文颜色、盒模型和减少动态效果规则存在。
- `T2.1-A03`：抽查组件 WXSS，不得重复输出带组件作用域的全局 `page` 规则。
- `T2.1-A04`：检查页面和组件源码，规格允许的精确几何值以外，不存在未解释的私有视觉常量。

### 4.4 反证抽查

- 把一个颜色令牌临时改成错误值，令牌合同测试必须失败。
- 临时加入未批准字号或阴影，禁止项扫描必须失败。
- 临时在全局样式加入纸纹背景，规则扫描必须失败。

### 4.5 禁止捷径

- 只检查令牌名称存在，不检查具体值。
- 在 `uni.scss` 和 `globals.scss` 重复维护同一组全局样式。
- 为通过截图临时在页面写入私有颜色或魔法间距。
- 用注释声称“与令牌一致”，但代码仍使用硬编码值。

### 4.6 必需证据

- 令牌合同测试结果；
- 禁止视觉值扫描结果；
- 生产 `app.wxss` 路径和抽查结论；
- 重复全局样式扫描结果；
- 本子项 warning 列表。

### 4.7 退出条件

`T2.1-M01` 至 `T2.1-M10`、`T2.1-A01` 至 `T2.1-A04` 全部通过，且反证抽查能够使验证失败。

## 5. Task 2.2：PageShell 与四类布局模板

### 5.1 验收目标

让 `PageShell` 统一处理顶部导航、微信胶囊避让、安全区、页面边距、原生页面滚动、键盘布局和四类页面模板。

### 5.2 固定接口门

- `T2.2-M01`：`PageLayout` 只包含 `quiet-landing / standard-flow / task-form / reading`。
- `T2.2-M02`：Props 与正式规格一致，不新增未经确认的公开参数。
- `T2.2-M03`：只发出 `back` 事件，不直接执行路由、保存、删除或草稿操作。
- `T2.2-M04`：六个插槽名称与正式规格完全一致。

### 5.3 结构与行为机器门

- `T2.2-M05`：`quiet-landing` 不渲染空导航占位。
- `T2.2-M06`：普通页面使用路由页面原生纵向滚动，不创建统一嵌套 `scroll-view`。
- `T2.2-M07`：`task-form` 结构顺序为 `intro → content → flexible-space → actions`。
- `T2.2-M08`：键盘关闭时，短表单操作区通过弹性空白下沉，不使用绝对定位。
- `T2.2-M09`：键盘打开时移除一屏最小高度，操作区回到普通文档流且仍可滚动到达。
- `T2.2-M10`：长内容不会被固定高度、`overflow:hidden` 或固定操作区截断。
- `T2.2-M11`：顶部导航标题相对视口居中，左右槽位保持对称语义。
- `T2.2-M12`：右侧槽位预留微信胶囊宽度和最小间隔。
- `T2.2-M13`：返回和右侧操作热区使用 `$pm-hit-target-min`，不得固定为某台设备的 CSS 像素。
- `T2.2-M14`：页面最大宽度为 `$pm-layout-max-width`，超过后水平居中，无横向滚动。
- `T2.2-M15`：运行时变量只被消费，不在普通页面重复调用平台 API。
- `T2.2-M16`：组件不保存业务状态，也不读取 Store 或 Repository。

### 5.4 响应式产物门

- `T2.2-A01`：`320px` 下无横向滚动、文字重叠和不可达操作。
- `T2.2-A02`：`393px` 下页面边距、导航和操作区符合标准坐标。
- `T2.2-A03`：`480px` 下内容宽度受限、点击热区不小于换算后的 `88rpx`。
- `T2.2-A04`：长内容增加后页面自然增长，正文和操作区均可到达。
- `T2.2-A05`：生产微信构建实际生成 `PageShell` 组件产物。

### 5.5 人工门

- `T2.2-H01`：微信开发者工具检查四类布局的短内容和长内容。
- `T2.2-H02`：检查键盘打开、关闭后操作区位置和滚动上下文。
- `T2.2-H03`：检查返回、标题和右侧操作不与微信胶囊重叠。
- `T2.2-H04`：检查页面返回后滚动位置符合调用页面的恢复合同。

### 5.6 反证抽查

- 临时交换 `flexible-space` 与 `actions` 顺序，结构测试必须失败。
- 临时把热区改成固定 `44px`，`480px` 检查必须失败。
- 临时加入嵌套 `scroll-view`，结构扫描必须失败。

### 5.7 禁止捷径

- 只测试布局类名存在。
- 用截图坐标或绝对定位模拟操作区下沉。
- 只在 `393px` 测试后推断其他宽度正确。
- 用浏览器 H5 预览代替微信运行检查。

### 5.8 必需证据与退出条件

提交接口测试、结构测试、三宽度检查、键盘检查、微信构建产物和人工记录。`T2.2-M01` 至 `T2.2-H04` 全部通过，或人工项真实登记外部阻碍后，才可进入 Reviewer 验收。

## 6. Task 2.3：基础操作与表单组件

### 6.1 验收目标

完成 `PrimaryButton`、`TextAction` 和 `FormField` 的固定公开接口、状态、反馈时序、表单视觉与事件纪律。

### 6.2 固定接口门

- `T2.3-M01`：三个组件的 Props、Events 和 Slots 与正式规格完全一致。
- `T2.3-M02`：未经项目负责人确认，不得新增 `variant`、`size`、`align`、`outline` 等公开变体。
- `T2.3-M03`：若正式需求无法通过既有接口实现，先提出接口变更方案，不得直接编码后补文档。

### 6.3 PrimaryButton 子标准

- `T2.3-M04`：默认、按下、禁用和加载状态使用正式令牌。
- `T2.3-M05`：`block` 宽度为 `100%`；`content` 使用内容宽度、最小 `376rpx`、最大 `100%`。
- `T2.3-M06`：`disabled` 与 `loading` 均不发出 `press`。
- `T2.3-M07`：一次有效触发只发出一次 `press`。
- `T2.3-M08`：加载状态不改变按钮宽度、圆角和页面位置。
- `T2.3-M09`：操作在 `150ms` 内完成时不显示加载文案；超过后才显示。
- `T2.3-M10`：已经显示的加载反馈遵守最短显示与立即错误/导航切换纪律。
- `T2.3-M11`：两行文案允许按钮增高，不缩小字号、不截断。
- `T2.3-M12`：危险操作颜色必须来自已确认令牌，不能使用 `darken()` 等派生值。

### 6.4 TextAction 子标准

- `T2.3-M13`：只支持 `default / muted / danger` 三种 tone。
- `T2.3-M14`：最小热区不小于 `$pm-hit-target-min`。
- `T2.3-M15`：禁用状态不发出 `press`。
- `T2.3-M16`：不提供任意对齐、背景填充或伪主按钮变体。
- `T2.3-M17`：危险 tone 只用于不可恢复操作。

### 6.5 FormField 子标准

- `T2.3-M18`：同时传入 `help` 和 `error` 时只显示 `error`。
- `T2.3-M19`：错误文案由页面传入，组件不自行生成产品文案。
- `T2.3-M20`：真实 `input` 和 `textarea` 使用规定的字体、背景、边界、圆角和内边距。
- `T2.3-M21`：聚焦时边框使用 `$pm-color-olive`，仍保持 `1px`，容器尺寸不跳动。
- `T2.3-M22`：插槽中的真实输入控件能够收到组件样式，不只在空容器上测试。
- `T2.3-M23`：三个文本域高度令牌可被页面稳定使用。
- `T2.3-M24`：错误不能只通过颜色表达。

### 6.6 产物与人工门

- `T2.3-A01`：微信生产构建生成三个组件及对应 WXSS。
- `T2.3-A02`：WXSS 不包含未批准的颜色、字号、阴影和派生色。
- `T2.3-H01`：微信开发者工具检查单行、两行、禁用、加载、聚焦、帮助和错误状态。
- `T2.3-H02`：快速连续点击只产生一次业务意图。

### 6.7 反证抽查

- 使用假时钟把时间推进到 `149ms`，加载文案必须仍不可见；推进到 `150ms` 后才可见。
- 临时移除禁用保护，重复事件测试必须失败。
- 临时把聚焦边框改为 `2px`，尺寸稳定测试必须失败。
- 使用真实插槽输入，证明样式测试不是只检查源码字符串。

### 6.8 禁止捷径与退出条件

不得只测试文本是否渲染、类名是否存在或按钮文件能否编译。`T2.3-M01` 至 `T2.3-H02` 全部通过，三类组件无接口漂移后，才可接受。

## 7. Task 2.4：内容与缺失状态组件

### 7.1 验收目标

完成 `MemoryEntry`、`MemoryList` 和 `MissingContentState`，保证内容顺序、长文本、空状态、失效照片和整行交互稳定。

### 7.2 机器门

- `T2.4-M01`：三个组件的固定 Props、Events 和 Slots 与规格一致。
- `T2.4-M02`：`MemoryEntry` 不格式化日期、不排序、不读取详情、不执行导航。
- `T2.4-M03`：有图时显示规定缩略图；无图时不保留空列。
- `T2.4-M04`：长摘要最多两行省略，文本列 `min-width:0`，不产生横向溢出。
- `T2.4-M05`：日期保持一行且使用 meta 令牌。
- `T2.4-M06`：整行只有一个平台可识别的按钮语义，点击任意有效区域只发出一次 `select(memoryId)`。
- `T2.4-M07`：缩略图替代说明真正进入可访问性属性，不只停留在类型字段。
- `T2.4-M08`：`MemoryList` 严格保持调用方顺序。
- `T2.4-M09`：第一条之前不画分隔线；条目之间使用正式边界令牌。
- `T2.4-M10`：空数组只渲染 `empty` 插槽，不生成占位数据。
- `T2.4-M11`：`footer` 不进入单条记忆交互区。
- `T2.4-M12`：缺失状态不显示技术错误码、堆栈或空白页。
- `T2.4-M13`：缺失状态只发出 `action`，不自行导航。
- `T2.4-M14`：初始化尚未完成时，不提前显示内容不存在。

### 7.3 产物与人工门

- `T2.4-A01`：微信生产构建生成三个组件。
- `T2.4-A02`：组件中不存在 Store、Repository、Storage、CloudBase 或路由调用。
- `T2.4-H01`：检查长中文、超长空间名、无照片和失效照片下无横向滚动。
- `T2.4-H02`：检查整行点击热区与视觉区域一致。

### 7.4 反证抽查

- 传入乱序数据，确认输出顺序与输入完全一致。
- 传入超长摘要，确认不会撑破页面。
- 临时在组件内部排序，顺序测试必须失败。
- 临时让缺失状态自行导航，边界扫描必须失败。

### 7.5 禁止捷径与退出条件

不得用静态样本证明长文本和空状态；不得使用普通 `<view @click>` 冒充按钮语义。`T2.4-M01` 至 `T2.4-H02` 全部通过后才可接受。

## 8. Task 2.5：ConfirmDialog 与 BottomSheet

### 8.1 验收目标

完成两项确认和三项选择覆盖层，保证遮罩纪律、pending 锁定、背景滚动、焦点恢复、安全区和关闭事件可靠。

### 8.2 固定接口与机器门

- `T2.5-M01`：两个组件公开接口与正式规格一致。
- `T2.5-M02`：`ConfirmDialog` 只支持确认和取消，不增加第三项操作。
- `T2.5-M03`：`BottomSheet` 使用 `default` 和 `actions` 插槽承载三项选择。
- `T2.5-M04`：`open=false` 时不渲染可交互遮罩。
- `T2.5-M05`：打开后阻止背景滚动和背景交互。
- `T2.5-M06`：关闭后恢复打开前的滚动位置。
- `T2.5-M07`：打开后焦点进入覆盖层，关闭后恢复到原操作。
- `T2.5-M08`：`pending` 时确认、取消、遮罩和系统返回路径全部锁定。
- `T2.5-M09`：失败后覆盖层保持打开，业务数据不变，确认与取消恢复可用。
- `T2.5-M10`：涉及删除、放弃输入和草稿替换时，遮罩不得关闭。

```text
|---|---|---|---|

- 无 / 标准ID、证据和修复建议

```
