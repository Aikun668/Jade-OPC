# 宠物记忆产品：首轮可点击验证原型设计

版本：v0.3  
日期：2026-07-16  
状态：已确认，待用户审阅后进入实施计划

> v0.3 决议优先于本文此前所有“沫沫”“示例照片”“无需真实上传”的表述：原型不再使用虚构宠物或预置照片。用户可从自己的设备选择一张照片；照片仅在当前浏览器会话中临时展示，不上传、不发送到服务器、不写入持久存储。照片入口与“想不起来 → 换一张照片”均使用同一条本地选图路径。

## 0. v0.3：本地照片体验边界

本轮需要验证的不是用户能否替虚构宠物编故事，而是用户是否愿意从 Ta 的真实照片开始，并在低压力下留下一点真实描述。

照片路径固定为：

```text
选择「一张照片」
  -> 从设备相册选择 Ta 的照片
  -> 明确说明“仅当前设备临时展示，不上传、不保存”
  -> 显示用户选择的照片
  -> 提问“看到这张照片时，你最先想起了什么？”
  -> 回答 / 想不起来 / 换一张照片 / 今天先停在这里
  -> 生成可编辑记忆草稿
  -> 用户保存后，照片与文字在当前浏览器会话的记忆空间中一起显示
```

原型不再保留任何沫沫、示例照片、预设示例回答或本地猫图资源。用户随时可以取消选图、换一张、切换到更轻的回忆入口或结束体验。

## 0.1 输入后的保存规则

用户完成一段输入后，主动作应为“先留下这段记忆”，直接保存用户原话并回到记忆空间。用户在已有输入时选择“今天就到这里”，也必须先保存该原话再结束；只有没有任何输入时，才安静结束且不创建空记录。

首版不为凑足片段数量而补写用户未提供的内容。每个保存条目都必须来自用户真实输入，可选关联其本地临时选择的照片。

## 1. 目的

本原型用于验证目标用户是否愿意使用“温和记忆访谈”这一核心闭环，而不是验证完整小程序的技术可行性或商业化。

首轮要得到的证据是：

1. 用户是否愿意从一个低压力入口开始；
2. 用户是否认为提问自然，而非被审问或被推动进入悲伤；
3. 用户暂时想不起来时，是否感到产品给了足够的自由和安全出口；
4. 用户是否理解并信任 AI 仅基于已提供内容整理的方式；
5. 用户是否接受“今天只留下两段记忆，也已经足够”的结束方式。

## 2. 原型形式与测试方式

原型是一个手机优先、可通过链接或二维码打开的轻量网页。用户无需电脑、账号、注册、真实上传或提供个人数据。

原型采用引导式测试：研究者在微信语音、视频或线下陪同中邀请用户自行点击；研究者不在每一步解释设计意图，而是观察用户的选择、犹豫和主动评论。

原型不连接真实 AI、云存储、提醒、分享或数据导出功能。所有内容仅是本地演示数据，关闭页面后不保留。

## 3. 首次进入的上下文

原型首屏不得出现“沫沫”或任何虚构宠物名称。用户首次进入时必须先理解：

1. 这是一个帮助宠物离世后用户整理真实记忆的私密空间；
2. 用户可以从照片、相遇、关系或普通日常开始；
3. 当前是无账号、无上传、无保存的示例体验。

首屏完成理解与信任建立后，用户主动点击“用示例体验一次”，才进入回忆入口选择。

## 4. 示例内容

使用一只虚构的猫“沫沫”作为示例宠物。用户选定一种回忆入口后，页面必须明确说明“接下来会用虚构的沫沫演示一次；这不是你的记忆，也不会保存”。示例照片与文字必须标注为“示例照片”或“示例内容”。

这样可以先验证交互与情绪感受，不把“是否愿意上传自己的私密照片”混入首轮结果。

示例图片采用用户提供的本地素材；含水印的图片不得用于原型。

## 5. 原型范围

### 4.1 包含

- 四个开始入口：日常、相遇、你们的关系、一张照片；
- 一张沫沫的示例照片；
- 一个产品说明首屏和一个主动进入示例的动作；
- 四个含义不同的回忆入口及其不同的第一问；
- 一个轻量问题和一个可选补充问题；
- 自由输入与预设示例回答；
- “想不起来”安全分支；
- 基于用户输入或示例回答生成的两条可编辑整理草稿；
- 保存后的只读查看状态；
- 在任意关键步骤离开或结束的低压力出口。

### 4.2 不包含

- 真实账号、登录、注册或用户身份；
- 真实照片、语音或文本上传；
- 远程保存、云端数据库或导出；
- 真实模型调用、内容识别或图像分析；
- 提醒、分享、纪念卡、生图、仪式和社区；
- 进度条、连续使用、完成度、打卡或任何增长性召回。

## 6. 可点击主线

四个入口必须是有效选择，不能合流到同一个问题。每个入口完成自己的第一问后，才汇合至可选补充、AI 整理草稿与保存状态。

```text
产品说明与信任声明
  -> 用户主动选择“用示例体验一次”
  -> 选择入口
  -> 明确说明“沫沫为虚构示例，不会保存”
  -> 对应入口的第一问
  -> 回答 / 跳过 / 想不起来
      -> 想不起来：具体回忆入口或安全结束
      -> 回答：可选补充问题与草稿
  -> AI 整理草稿
  -> 用户确认保存
  -> 安静查看与结束
```

## 7. 关键状态

### 7.1 产品说明与信任声明

标题：`留住那些你不想忘记的小事`  
说明：`一个私密的宠物记忆空间。你可以从一张照片、第一次相遇，或一个普通日常开始，慢慢留下真实片段。`

唯一主动作：`用示例体验一次`。

底部必须显示：`无需账号 · 不会上传或保存你的内容`。

验证点：用户是否在进入前理解产品用途与本次体验的边界。

### 7.2 入口选择

标题：`今天想从哪里开始？`。

四个入口必须同时展示名称与解释：

- 日常：`从它平时的一个小习惯开始`；
- 相遇：`回想第一次见到它的样子`；
- 你们的关系：`用一句话说说你们`；
- 一张照片：`让照片帮你打开一个片段`。

验证点：用户是否理解每项差异，并能说出自己最愿意选择的入口。

### 7.3 沫沫示例说明与四条第一问

每条入口进入后，顶部都显示：`接下来会用虚构的沫沫演示一次；这不是你的记忆，也不会保存。`

第一问根据入口改变。所有直接面向测试用户的宠物指代统一使用 `Ta`，不要求测试用户替虚构宠物编造经历：

- 日常：`Ta 最喜欢待在家里的哪个地方？`；
- 相遇：`还记得第一次见到 Ta 时，Ta 是什么样子吗？`；
- 你们的关系：`如果用一句话形容你和 Ta 的关系，会是什么？`；
- 一张照片：先从真实示例照片中选择一张，再问：`你为什么会停在这张照片上？`。

照片入口使用用户提供的无水印猫照片；其他三条入口不要求先出现照片。

验证点：四条路径是否真的呈现不同的回忆入口，而不是不同名称的同一流程。

### 7.4 想不起来分支

文案：`没关系，不需要现在想起来。`  
说明：`我们可以换一个更轻的入口，或者先停在这里。`

选择项：从声音开始、从动作开始、从常待的地方开始、看看其他照片、今天就到这里。

验证点：用户是否感到被允许暂停，而非被要求继续完成流程。

### 7.5 轻量回答与补充

提供可选示例回答：`它总喜欢在午后晒太阳。`  
允许用户自由改写或输入测试文本。

可选补充问题：`还有什么小习惯，是你一想到就会认出它的？`

补充问题同样提供跳过和结束出口。

验证点：用户是否认为一小段回答就足够，且不会产生“必须记得更多”的压力。

### 7.6 AI 整理草稿

明确标记：`根据刚才的内容整理，仍可修改。`

默认草稿示例：

- `沫沫喜欢在午后去窗边晒太阳。`
- `阳光落下来时，它常常安静地待在那里。`

提供：修改原话、保存这两段、今天先到这里。

验证点：用户是否理解整理内容的来源，并认为自己拥有最终确认权。

### 7.7 安静保存与查看

标题：`今天留下了两段记忆。`

展示两条已保存的记忆。出口为：再记一段、以后再继续、今天就到这里。

三种选择的视觉权重相近；不出现完成度、提醒、分享、注册或转化动作。

验证点：用户是否认可查看与结束本身就是完整使用。

## 8. 视觉与交互原则

视觉采用暖象牙白底色、低饱和橄榄灰绿强调色、深灰褐文字、细描边与充足留白；整体安静、私密、克制，避免哀伤化和治疗化表达。

### 8.1 按钮与选择控件

按钮应像纸页上的温和选择，而非营销页 CTA 或悬浮组件。采用以下层级：

| 类型 | 使用场景 | 尺寸与文字 | 圆角 | 阴影 |
|---|---|---|---|---|
| 主动作 | 用示例体验一次、保存这两段 | 高 48px；15px；500 字重 | 14px | 仅使用 `0 3px 10px rgba(66,62,55,.08)` 的极轻阴影 |
| 入口卡 | 日常、相遇、关系、照片 | 高 92px；标题 15px；说明 12.5px | 18px | 默认无阴影 |
| 次要操作 | 以后再继续、今天就到这里 | 高 44px；14px；400 字重 | 14px | 无阴影 |
| 文字操作 | 想不起来、换一个问题 | 14px；400 字重 | 无背景 | 无阴影 |

圆角层级固定为：14px 用于操作按钮与输入框；18px 用于入口卡；22px 用于照片与记忆内容卡；28px 用于大页面容器。`999px` 仅用于小标签，不得用于主按钮。

入口卡标题使用 18px、500 字重；说明使用 12.5px、400 字重。标题和说明必须清楚拉开层级，不能显示为两级相近的小字。

除主动作外，默认不使用实色填充。入口卡以暖白背景和极细描边呈现；选中时仅以极淡灰绿色背景与橄榄灰绿边框反馈。按钮按下时下沉 1px、颜色略深，不使用弹跳、缩放或显著悬浮动画。

交互规则：

- 任意关键步骤可跳过、暂停或结束；
- “想不起来”进入降低难度的分支，不重复追问；
- 整理草稿不能自动成为最终记忆，必须经过用户选择保存；
- 所有数据均为演示数据，不暗示已真实保存；
- “随时暂停”只在用户已进入回忆路径后显示，不出现在产品说明首屏；
- 不使用任何挽留、愧疚、催促或任务化文案。

## 9. 引导与访谈脚本

测试开始时说明：

> 这不是正式产品，也不会收集你的真实内容。我想请你按自己的感觉点一遍；哪里不想点、哪里觉得奇怪，都请直接告诉我。

测试过程中，研究者仅在用户卡住时说明“你可以按自己的感觉继续、跳过或结束”，不替产品辩护，也不解释某个设计为何存在。

结束后依次询问：

1. 你最愿意从哪个入口开始？为什么？
2. 哪一步让你犹豫、想退出或觉得不舒服？
3. 哪一句话让你觉得被理解，或反而不理解？
4. 如果正式产品可以这样使用，你会愿意留下真实的一段记忆吗？为什么？

## 10. 结果记录

每位受访者记录以下内容：

- 是否愿意完成主线；
- 首选入口和未选择入口；
- 主动停顿、跳过或退出的位置；
- 对问题、AI 整理、隐私与结束方式的原话反馈；
- 是否愿意在未来体验保存真实内容的版本；
- 明确的风险、误解或不适点。

首轮不以“喜欢”作为成功标准。更重要的是发现：用户是否愿意开始、在哪些地方失去控制感，以及产品是否确实被理解为私密记忆整理空间而非心理治疗、普通相册或 AI 宠物聊天。

## 11. 验收标准

在手机浏览器中，受访者无需说明即可完成主线，或在任一节点自然地进入跳过与结束路径。

原型必须正确表达：产品用途、示例身份、无需账号与不保存、四条入口的实际差异、想不起来也没关系、AI 整理可修改、今天结束也可以。

保存或安全结束后，用户必须进入一个可持续查看的“记忆空间首页”。该页面在下方保留本次已完成的记忆片段，并提供“再留一段”入口；用户切换入口或新建片段时，不得清空已完成片段。

原型不得出现范围外功能或与既有核心业务规则冲突的表现。
